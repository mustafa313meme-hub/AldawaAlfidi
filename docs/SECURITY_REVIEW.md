# SECURITY REVIEW

> مراجعة ذاتية للكود الذي كتبته، **وليست اختبار اختراق**. الكود لم يُشغَّل ولم يُفحص بأدوات (SAST/DAST/`npm audit`). ما يلي ما يوجد في الكود وما ينقص.

## الفجوات والمخاطر (مرتبة بالأهمية)
1. **الكود لم يُترجَم ولم يُشغَّل.** أي ضابط أعلاه هو «مكتوب» وليس «مُثبَت». شغّل `scripts/acceptance-test.mjs` (فيه فحوص صلاحيات 28 و10 أعلاه) قبل الاعتماد على أي منها.
2. **`npm audit` لم يُشغَّل** (لا شبكة). شغّله وأصلح الثغرات High/Critical (CI يشغّله).
3. **لا مصادقة ثنائية (2FA)** لحسابات الإدارة. أوصي بها لـ Super Admin/المحاسب قبل الإنتاج.
4. **التحقق من الجهاز عبر `x-device-id` غير موثَّق بتوقيع**: أي عميل يعرف معرّف جهاز مستخدمه يستطيع انتحاله في الـ Idempotency (لا يتجاوز صلاحياته). ربط الجهاز بشهادة/Attestation (Play Integrity/App Attest) غير مبني.
5. **تسجيل الموقع (GPS) قابل للتزوير** (Mock location)؛ النظام يعلّم الزيارات المشكوك بها ولا يمنعها بشكل قاطع (قرار SRS §32).
6. **بيانات العملاء (هواتف/عناوين) غير مشفرة على مستوى الحقل** في قاعدة البيانات؛ الحماية بالأذونات والشبكة وتشفير القرص والنسخ.
7. **استعادة كلمة المرور بلا قناة إرسال** (SMS/Email غير مبنيين)؛ حالياً يعيّن المدير كلمة المرور (`users.reset_password`).
8. **الإشعارات الفورية (Push)** غير مبنية فعلاً (`PUSH_PROVIDER` ينتظر Firebase).
9. **حدّ المعدل لكل IP**: خلف Caddy يُقرأ الـ IP الحقيقي (`trust proxy = 1`)؛ إن نُشر بلا وكيل فعطّل `trust proxy` وإلا يمكن تزوير `X-Forwarded-For`.
10. **لا Error tracking (Sentry) ولا مراقبة (Prometheus/Uptime)**؛ فقط health check وسجلات.
11. **لا WAF ولا حماية DDoS**؛ فكّر بـ Cloudflare أمام النطاق.
12. **سياسة كلمات المرور**: الحد الأدنى 8 أحرف فقط بلا قائمة كلمات شائعة؛ ارفعها إلى 12 وأضف فحص القوائم.
13. **المصادقة لا تدعم SSO**.

## قبل الإنتاج: اختبارات مطلوبة
- اختبار اختراق خارجي للـ API (OWASP API Top 10): خاصة BOLA (الوصول لعملاء غيرك)، وتصعيد الصلاحيات، وتجاوز معدل المحاولات.
- مراجعة كل استعلام `$queryRaw` يدوياً (حقن/أداء).
- اختبار تحميل: 50 مندوباً يزامنون في الوقت نفسه.

## إضافة: واجهة الإدارة (Admin Web)
| الضابط | الحالة |
|---|---|
| XSS | لا `innerHTML` في أي ملف؛ كل نص عبر `textContent`. مُختبَر بحمولة `<img onerror>` في اسم عميل |
| CSP | `default-src 'self'` (لا inline script/style، لا اتصال خارجي) في `index.html`؛ وCaddy يضيف `X-Frame-Options: DENY` وHSTS و`nosniff` |
| الرموز | `sessionStorage` (تُمحى بإغلاق التبويب) + تجديد تلقائي. **مخاطرة:** أي XSS مستقبلية تسرقها. بديل أقوى: `HttpOnly` cookie مع حماية CSRF (غير مبني) |
| إخفاء الصفحات حسب الصلاحية | للراحة فقط؛ الفرض الحقيقي في الـ API |
| الاستثناءات البرمجية | لا تُعرض للمستخدم |
| تسرّب ملفات الاختبار | Caddy يردّ 404 على `/test/*` و`/README.md` |
| ما لم يُفحص | اختبار اختراق للواجهة، ومراجعة المكتبات (لا مكتبات خارجية أصلاً) |
